# 企业微信试验接入

## 当前已落地

- 自建应用 `access_token` 获取与 Redis 缓存。
- 应用可见范围内的成员详情、部门列表读取。
- 自建应用文本消息投递与连通性检查。
- 后台企业微信 OAuth 登录；尚未开通的企微企业会在首次登录时自动创建企业、企业管理员和企业名片草稿。
- 安全模式回调 URL 校验、SHA-1 签名校验、AES-CBC 解密和幂等入库。
- 客户联系「联系我」创建、客户详情读取的服务端适配器。
- 员工名片专属企微二维码，以及新增外部联系人的名片归因、线索创建和负责人通知。
- 企业微信成员标识、成员资料和回调正文均加密保存；检索只使用不可逆 HMAC。

## 企业微信管理后台配置

1. 在「应用管理」创建自建应用，应用名称建议为「数智名片」。
2. 应用可见范围至少包含试验成员；成员和部门接口只会返回该范围内的数据。
3. 网页授权可信域名应与管理后台正式 HTTPS 域名一致。
4. OAuth 回调地址配置为：

   `https://<正式域名>/c/admin/wecom/callback`

5. 接收消息服务器 URL 配置为：

   `https://<正式域名>/c/api/v1/integrations/wecom/callback`

6. 回调使用安全模式，并把后台生成的 Token 与 EncodingAESKey 交给部署密钥管理。
7. 如启用客户联系接口，还需在「客户联系 → 客户 → API」中把该自建应用加入可调用应用。

生产环境不能使用裸 IP 的 HTTP 回调。OAuth 回调和企微服务器回调都应先准备可验证的 HTTPS 域名。

## 部署变量

以下值只能写入服务器密钥文件或密钥管理服务，不得提交到仓库：

```dotenv
WECOM_CORP_ID=
WECOM_AGENT_ID=
WECOM_APP_SECRET=
WECOM_TENANT_ID=
WECOM_COMPANY_ID=
WECOM_OAUTH_REDIRECT_URI=https://<正式域名>/c/admin/wecom/callback
WECOM_CALLBACK_TOKEN=
WECOM_CALLBACK_ENCODING_AES_KEY=
```

`WECOM_TENANT_ID` 和 `WECOM_COMPANY_ID` 是本系统数据库中的企业范围 UUID，不是企微后台编号。首次企微登录建企不要求预填这两个值；只有启用回调事件处理时才需要把它们设置为已创建的企业范围。

## 首次绑定与日常登录

1. 企微企业第一次从工作台打开应用时，系统读取通讯录根部门作为企业名称。
2. 系统原子创建企业、企业名片草稿，并把首位活跃成员设为企业管理员。
3. 同一企微企业后续登录会复用已创建的企业；未被管理员加入后台权限的其他成员不能自行提权。
4. 已有后台企业仍可通过 `GET /api/v1/auth/wecom/bind-url` 和 `POST /api/v1/auth/wecom/bind` 完成管理员授权的账号绑定。

OAuth `state` 是 Redis 保存的一次性 64 位随机值，符合企微只允许字母数字且不超过 128 字节的限制；成功或失败消费后不可重放。

## 放入企业微信工作台

推荐把现有管理网站直接作为自建应用的 H5 应用主页，无需另建一套小程序页面：

1. 在企业微信「应用管理 → 数智名片」中把应用主页设置为：

   `https://<正式域名>/c/admin/wecom/entry`

2. 把 `<正式域名>` 配置为该应用的网页授权可信域名，域名和端口必须与实际访问地址一致。
3. 保持 OAuth 回调地址为：

   `https://<正式域名>/c/admin/wecom/callback`

4. 把应用可见范围限制为允许使用数智名片后台的成员。

工作台入口会先恢复已有安全会话；没有会话时自动发起企业微信 OAuth，不展示密码登录页。OAuth 成功后，首次开通者直接进入新企业的企业概览；之后由企业管理员维护成员和发布内容。

## 运维检查接口

- `GET /api/v1/platform/integrations/wecom/status?probe=true`
- `GET /api/v1/platform/integrations/wecom/departments`
- `POST /api/v1/platform/integrations/wecom/test-message`

以上接口仅平台管理员可用，响应不会返回 CorpSecret、Token 或 EncodingAESKey。
