# 平台控制台与企业工作台分阶段方案

> 状态：已冻结的产品方向与实施路线图
> 更新日期：2026-08-23
> 适用范围：平台控制台、企业工作台、资料辅助建企、企业 AI 配置、协会/商会扩展边界
> 实施真源：`openspec/changes/unify-platform-enterprise-llm-import-control-plane/`
> 说明：本文用于统一产品目标、问题、分期和验收口径；OpenSpec 的 `plan.md` 仍是代码实施进度的唯一真源。

## 1. 总目标

把当前系统收束成真正的多企业运营平台：

- **企业**是数据隔离、内容经营、成员管理、名片发布和 AI 使用的基本单元。
- **平台**负责查看全局经营状态、开通企业、处理异常、维护平台安全边界和受委托配置，不替企业日常经营。
- **企业管理员**管理本企业资料、内容、名片、成员、AI、访问转化与通知。
- **协会/商会**未来作为跨企业管理范围存在，不成为破坏企业隔离的父租户。
- **订阅、合同和账务**是后续治理层，本阶段只留兼容边界，不建设完整计费系统。

设计原则：

1. 平台看全局和企业级聚合，不读取企业私域正文和访客敏感信息。
2. 企业自主创建和发布名片，平台建企不自动制造公开内容。
3. 同一个业务指标只保留一套服务端口径，不在不同页面前端拼装第二套数据。
4. 日常界面显示业务语言，技术事件、原始错误码和审计细节进入诊断能力。
5. 功能不减少，但通过二级页、渐进披露和上下文入口降低操作复杂度。
6. UI 继承根 `DESIGN.md`：克制、清晰、可信；不引入渐变、玻璃拟态和无真实数据的装饰图表。

## 2. 已发现的问题

### 2.1 平台控制台

#### 导航与信息架构

- “员工概览”“访客概览”作为平台一级入口过细，和运营概览、企业详情中的数据重复。
- “审计记录”是故障排查能力，不适合占据日常运营导航。
- 企业管理的完整详情放在抽屉中，无法独立刷新、复制链接、保留当前位置，也不适合承载越来越多的企业治理信息。
- 平台导航混合了运营、开通、技术运维和设置，平台管理员难以快速判断下一步要处理什么。

#### 数据与指标

- 运营总览、企业列表和企业详情容易形成不同口径，前端拼接总数会导致数字不一致。
- 原有员工/访客概览的独立页面放大了重复指标，却没有形成企业状态、活跃度、任务和服务风险的统一判断。
- 平台只能看到企业是否存在，难以按活跃度、待处理任务和套餐风险筛选真正需要关注的企业。

#### 任务中心

- 原任务中心偏向 outbox 和业务事件投递，成功的技术事件也进入主列表，运营人员无法区分“需要处理的任务”和“系统正常流转日志”。
- 原始事件码和技术状态直接污染界面，缺少按企业聚合的工作视图。
- 企业详情缺少近期任务摘要，也无法一键跳转到已带企业筛选的任务中心。

#### 建企与企业身份

- 建企流程曾要求平台管理员确认或生成“初始草稿名片”，把企业身份开通和企业内容经营绑在了一起。
- 企业正式名称、对外简称、统一社会信用代码、内部 tenant/company UUID 和登录账号曾存在语义混用风险。
- 企业管理员只是企业账号与 membership，不应为了登录平台被强制创建为企业员工。
- 辅助建企生成的候选内容必须先人工确认，不能自动发布、生成公开链接或隐式代替企业经营。

#### 平台权限与隐私

- 平台需要跨企业运营视图，但不能因此读取访客 PII、对话正文、线索正文、知识正文、联系人隐私字段或密钥。
- “代企业配置”若通过模拟登录实现，会破坏责任边界和审计可信度。
- 技术审计必须保留，但应该从日常导航降级为超级管理员/故障排查入口。

### 2.2 企业工作台

#### 导航与对象关系

- 访问、访客画像、对话、线索等页面被拆成多个孤立列表，用户难以从一次访问追到长期访客、对话和转化结果。
- “销售线索”独立一级页面容易把产品带向轻量 CRM，但当前真正目标是名片访问与内容转化闭环。
- 产品新建/编辑、访问查看等复杂操作放在列表或抽屉中，不利于刷新、返回、深链和移动端操作。
- 企业工作台栏目较多，所有分组同时展开会造成导航噪声。

#### 企业资料和设置混杂

- 企业资料曾混入 LLM API、模型、Key、AI 回答范围、通知接收人、企业微信推送和隐私留存等不属于企业身份的设置。
- 回答策略和模型接入是两个不同问题：一个决定“允许怎么答”，另一个决定“使用哪个模型与额度”，不应混在一页。
- 通知策略、隐私策略和企业对外资料缺少各自稳定入口。

#### 通知噪声

- 普通访问如果逐条实时通知，会淹没真正重要的留资与高意向事件。
- 通知需要明确接收人、渠道和汇总频率，并在工作台内可追溯。

#### 名片与内容引用

- 企业建成后应该自行创建企业名片和员工名片；平台不能预先替企业发布名片。
- 核心业务、案例、FAQ 等是企业主数据，名片只是引用和展示；工作台修改主数据时，需要明确显示关联名片数量并二次确认是否一键更新。
- 名片级允许有展示数量、排序和样式覆盖，但不能复制一份脱离主数据的内容真源。

#### 资料导入与智能候选

- 资料导入曾出现候选切分过碎、字段大量“待补”、不同文件产生相似候选、任务 ID 难理解等问题。
- 导入页面需要左侧按企业资料、核心业务、案例、FAQ 分类，并支持快速转移分类；切换分类不能清空已有字段。
- 智能候选应保留原文证据、置信度、缺失字段和人工修改，确认后写入草稿，不自动发布。
- 导入任务需要人类可读名称、进度浮窗、离开页面后继续处理和完成后返回审核。

## 3. 目标信息架构

### 3.1 平台控制台

平台侧围绕“全局经营、企业开通、异常处理、安全治理”组织：

1. **运营概览**：平台核心指标、待处理事项和服务风险。
2. **企业管理**：企业列表、筛选和企业独立详情页。
3. **开通与交付**：手工建企、资料辅助建企、临时凭据交付。
4. **任务中心**：运营任务时间流与企业视图。
5. **服务状态**：API、数据库、Worker、存储等诊断信息。
6. **平台 AI 设置**：供应商/模型白名单、默认模型和安全策略。
7. **协会管理**：P3 的平台级跨企业治理入口。

以下能力不再作为日常一级导航：

- 员工概览、访客概览：合并进运营概览和企业详情。
- 审计记录：保留深链和超级管理员诊断入口。
- 技术事件/outbox：保留在审计或服务健康中，不进入运营任务主列表。

### 3.2 企业工作台

企业侧按工作域渐进展开：

1. **工作台**：经营概览、待办和最近任务。
2. **客户增长**：访问记录、访客画像、AI 对话和转化结果。
3. **内容与智能**：资料导入、企业资料、核心业务、案例、FAQ、产品、知识和回答策略。
4. **名片**：企业名片、员工名片、模板、发布和公开页。
5. **企业治理**：企业员工、通知设置、数据与隐私、导出。
6. **AI 设置**：模型接入与额度；与回答策略分离。
7. **更多工具**：低频能力，不占据主工作流。

只有当前工作域展开；稳定 URL、权限和商业权益 ID 保持兼容。

## 4. P0：结构纠偏与安全边界

P0 先修正错误的信息架构和业务责任，不扩张新业务。

### 4.1 平台导航收束

- 删除“员工概览”“访客概览”两个平台一级入口，数据并入运营概览。
- 删除“审计记录”日常侧栏入口，保留审计数据、API 和受保护深链。
- 保留服务状态与平台 AI 设置，技术事件不进入运营任务主列表。

**验收：**

- 平台侧栏不存在员工概览、访客概览和日常审计入口。
- 旧链接有兼容跳转或明确权限结果，不出现空白页。
- 审计数据和故障排查 API 没有被删除。

### 4.2 企业详情改为独立二级页

企业列表进入 `/platform/enterprises/:companyId/:section`。完整详情不再依赖抽屉；抽屉最多保留轻预览。

企业详情规划八个区块：

1. 概览；
2. 运营数据；
3. 成员与名片；
4. 内容与资料；
5. 最近任务；
6. AI 配置；
7. 套餐与功能授权；
8. 操作记录。

**验收：** 页面可刷新、可复制 URL、可返回列表并保留筛选；无 mock 指标和隐私正文。

### 4.3 建企取消初始名片

平台建企只创建：

- 企业身份与隔离空间；
- 企业管理员账号/membership；
- 一次性临时密码；
- 默认功能授权；
- 可选的资料导入历史和未发布内容草稿。

平台不创建名片、slug 或公开链接。企业管理员登录后自行创建、确认和发布企业名片/员工名片。

### 4.4 企业身份字段分离

- `company_id` / `tenant_id`：系统内部不可变 UUID，承担关联和 RLS。
- 企业正式名称：工商或组织正式名称。
- 对外简称：公开展示名称。
- 主体类型：国内企业、组织等。
- 统一社会信用代码：国内企业的法定身份字段。
- `business_tenant_key`：运营可见的稳定业务租户标识。国内企业由规范化信用代码派生，例外主体由服务端生成。
- 管理员登录账号：个人登录身份，不等于企业信用代码，也不自动成为员工。

### 4.5 运营任务去技术事件化

运营任务最小模型：

- `task_id`、企业、任务类型、业务状态、严重度；
- 标题、业务摘要、创建/更新时间；
- 来源对象与可处理入口；
- 是否需要人工处理、失败原因的业务翻译；
- 内部事件码只在诊断详情显示。

纳入：企业开通、资料导入、内容审核、企业状态风险、服务有效性风险。

排除：正常完成的 outbox 投递、无须人工处理的技术事件。

### 4.6 企业资料和设置拆分

- **企业资料**：正式名、简称、信用代码、行业、官网、地址、简介、Logo/品牌展示。
- **AI 设置 / 模型接入**：供应商、模型、Key、额度。
- **AI 设置 / 回答策略**：回答边界、知识范围、通用问答策略。
- **通知设置**：首次访问提醒、行为报告、接收人、企业微信推送。
- **数据与隐私**：画像版本、同意状态、留存期限和隐私请求入口。

### 4.7 企业对象二级页

- 访问详情：`/visits/:visitId`，展示名片、来源、时间、停留/路径、对话、是否留资、匿名访客关联和脱敏状态；严格区分一次访问与长期访客档案。
- 产品：`/products/new`、`/products/:id`；列表只负责搜索和状态，详情负责内容、展示、分发和版本。
- 销售线索不再作为独立一级页面；底层转化数据保留，在访问详情和概览展示“未留资/已留资/待跟进”。

### 4.8 P0 当前状态

截至提交 `b9d037b`：主要代码和数据合同已实现；真实页面保存/刷新回显和部分 390px 验证已完成。完整跨角色端到端证据、全部兼容链接和独立 Checker 仍以 OpenSpec `plan.md` 为准，不能仅凭本文宣称全量验收完成。

## 5. P1：统一运营读模型与高效工作流

### 5.1 两层运营看板

平台级：

- 入驻、活跃、待激活企业；
- 近 30 天访问、独立访客、对话、已同意留资；
- 已发布名片；
- 待处理/失败任务；
- 服务风险和 AI readiness。

企业级：

- 成员、名片、访问、访客、对话、留资；
- 资料完成度；
- 最近任务；
- 套餐、额度和到期状态。

指标必须来自服务端统一读模型；平台概览、企业列表和企业详情复用同一口径。

### 5.2 企业列表经营筛选

支持按状态、30 天活跃度、待处理任务和套餐风险筛选/排序。点击企业进入同口径详情，不复制第二套统计逻辑。

### 5.3 任务中心双视图

两种视图共用同一数据源和筛选：

- **时间流**：按最近更新时间倒序。
- **企业视图**：按企业分组，显示待处理数、进行中数和最近任务。

共同筛选项：企业、状态、任务类型、时间范围。企业详情只显示最近 5–10 条，并可跳转到已带企业筛选的任务中心。

### 5.4 主数据与名片引用闭环

- 核心业务、案例、FAQ、产品和企业资料是企业主数据。
- 编辑发布前显示关联名片数量并二次确认。
- 用户选择“一键更新”后，引用该内容的名片同步读取新版本。
- 保留内容历史和可回退版本。
- 名片只保存展示开关、排序、数量和样式覆盖，不复制业务正文。

### 5.5 通知降噪

- 留资和高意向事件实时通知。
- 普通访问按日汇总。
- 通知默认先在工作台内呈现；企业微信等渠道按企业设置投递。
- 通知任务幂等，避免重复推送。

### 5.6 资料导入体验

- 任务采用可读名称，默认格式为“企业名称·资料导入·日期·第 N 次”，允许改名，UUID 仅作次要元数据。
- 候选左侧按企业资料、核心业务、案例、FAQ 分类和计数，可快速转移分类。
- 中间逐卡审核，支持上一条/下一条、自动保存、原文证据和缺失字段提示。
- 任务浮窗在切换页面后继续显示阶段、进度、失败或完成状态；完成后可返回准确批次。
- 重复资料提示但允许作为新版本导入。
- 未完成任务 24 小时进入过期状态；30 天后受限清理临时资源，保留脱敏审计摘要。

### 5.7 状态完整性

所有指标、列表、任务和详情必须覆盖：loading、empty、error、permission、success。

桌面与 390px 都不能出现逐日零值长表、字段挤压、页面横向溢出或原始事件码主导界面。

### 5.8 P1 当前状态

主要 API、读模型、导航和页面结构已实现。仍需按 OpenSpec 完成平台与企业真实网站全流程、桌面/390px 代表性截图、兼容链接、失败路径和独立验证映射。

## 6. P2：企业模型接入与平台安全策略

P2 解决“企业使用什么模型”，不和回答策略混成一页。

### 6.1 已冻结方案

- 平台维护供应商/模型白名单、全局安全策略、默认模型和平台预算硬上限。
- 企业可以选择平台托管模型，也可以配置自己的加密 API Key（BYOK）。
- 企业只能从平台允许的 provider/base URL/model 中选择，不能绕过白名单、安全门和限额。
- 企业配置独立预算上限，但不能高于平台 profile 的硬上限。
- Key 只写入、不回显；服务端加密保存，前端只看到是否已配置和脱敏提示。
- 所有更新使用 optimistic version，过期写入返回冲突。
- 平台可“受委托代配”，必须记录原因、操作者、版本，并在企业工作台内通知；禁止模拟登录。
- 公开 Chat 和企业资料导入按请求解析该企业的有效配置；未配置企业回退到平台当前主配置。
- 高风险回答边界仍由平台安全策略控制，不因企业 BYOK 放宽。

### 6.2 P2 当前状态

截至 `b9d037b`，企业模型访问数据边界、自助/受委托 API、有效配置解析、企业模型接入页、密钥遮罩、预算限制、审计与工作台通知已实现并提交。仍应保留真实 managed/BYOK 成功与失败路径、白名单拒绝、陈旧版本和密钥不泄漏的发布前回归证据。

## 7. P3：协会/商会跨企业治理扩展点

### 7.1 已冻结方案

- 协会/商会不是父租户，不拥有成员企业数据，也不改变企业 RLS。
- 企业仍然独立隔离；协会仅保存跨企业 membership 引用。
- 平台可维护协会成员企业、会员等级、席位和权益分配。
- 平台只返回协会汇总和安全企业字段，不返回成员企业访客 PII、对话、线索、知识正文或密钥。
- 协会、计费主体、企业和订阅账号必须是分离概念。
- 成员关系必须防重复、校验协会/企业类型，并支持安全解除。

### 7.2 明确延后

- 协会登录账号与独立控制台；
- 协会代管企业的正式权限矩阵；
- 协会跨企业内容或人员访问；
- 会费、名额采购、真实账务和分账。

### 7.3 P3 当前状态

截至 `b9d037b`，跨企业 membership 模型、平台专属 API、会员等级/席位/权益字段和最小平台管理界面已实现。正式协会权限矩阵与账务仍未冻结，不应从现有 membership 推导额外数据权限。

## 8. P4：商业与账务边界（本阶段非目标）

P4 暂不建设：

- 合同管理；
- 续费流程；
- 在线支付；
- 真实账务、发票、退款；
- 协会分账；
- 完整订阅计费系统。

当前只保留兼容边界：企业、协会、计费主体、订阅账号和权益分配分离；套餐/额度/到期字段可用于运营提醒，但不能被描述成真实财务账本。

## 10. 兼容、回滚与失败出口

- 旧稳定路由尽量保留兼容跳转；所有链接继续使用 `APP_BASE_PATH/appHref`。
- 新企业详情、访问详情和产品详情使用独立 URL；旧抽屉/聚合链接可临时跳转。
- 新建企不创建名片；历史开通记录允许保留旧 initial-card 关联，但不作为新流程依赖。
- 平台新页面失败时可隐藏路由，不删除企业、导入批次、内容草稿、LLM 密文或协会关系历史。
- LLM 配置失败时保持企业业务可用；资料解析不依赖 LLM，智能候选退化为人工填写。
- 密钥泄漏、跨租户访问、临时账号越权、自动发布、重复确认、错误计费或迁移数据风险均为硬阻塞，不能降级为普通警告。
