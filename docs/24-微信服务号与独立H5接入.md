# 微信服务号与独立 H5 接入

日期：2026-09-21。范围：普通微信登录、制作和管理个人名片、发布并分享。

## 需要准备的资料

| 项目 | 需要提供或确认 | 用途 |
| --- | --- | --- |
| 服务号名称 | 名称、认证状态、后台是否具备网页授权权限 | 确认接入账号及可用能力 |
| AppID | 服务号 AppID，可通过聊天提供 | 构造微信授权及 JS-SDK 配置 |
| AppSecret | 在服务器安全配置，不通过聊天或代码仓库传递 | 服务端换取微信身份及接口凭证 |
| 正式域名 | H5 的 HTTPS 域名；有域名解析和网站部署权限 | 菜单入口、网页授权回调、公开名片 |
| 服务号后台权限 | 能设置菜单、网页授权域名、JS 接口安全域名和 IP 白名单 | 完成微信侧接入 |
| 域名校验文件 | 后台下载的 `MP_verify_*.txt`，原文件名及内容 | 放到对应网站根路径，完成域名校验 |
| 服务器管理入口 | 通过已有安全访问方式交接，确认部署和配置权限 | 数据迁移、服务部署、密钥注入和日志核验 |

现在可以先提供：**服务号名称、认证状态、准备使用的域名**。AppID 随后补齐；不需要将 AppSecret 发到聊天里。

服务器出口公网 IP 由部署环境实测后填入白名单，不能把网站解析 IP 直接当成出口 IP。当前流程不需要企微 CorpID、AgentID、SuiteID，不需要支付商户号，也不接收公众号消息，因此暂不需要消息回调 Token / EncodingAESKey。

## 入口与配置

正式站点通过同一个 HTTPS 域名提供，管理端部署在 `/c/admin/`，API 位于 `/c/api/v1/`。

| 位置 | 地址或设置 |
| --- | --- |
| 服务号菜单“我的名片” | `https://<域名>/c/admin/wechat/entry` |
| 微信网页授权回调 | `https://<域名>/c/admin/wechat/callback` |
| 已发布名片 | `https://<域名>/c/<slug>` |
| 网页授权域名 | 回调地址所属域名，按公众号后台要求填写 |
| JS 接口安全域名 | 公开名片所属域名，按公众号后台要求填写 |
| 业务域名 | 同一 H5 域名，按后台实际要求配置 |
| IP 白名单 | 调用微信服务端 API 的服务器出口公网 IP |

服务端环境变量：

```dotenv
WECHAT_APP_ID=wx你的服务号AppID
WECHAT_APP_SECRET=通过服务器密钥配置注入
WECHAT_OAUTH_REDIRECT_URI=https://你的域名/c/admin/wechat/callback
WECHAT_TIMEOUT_SECONDS=8
PUBLIC_CARD_BASE_URL=https://你的域名
STAFF_AUTH_COOKIE_SECURE=true
```

`WECHAT_APP_SECRET` 不能使用 `VITE_` 前缀。运行时需要 Redis 存储一次性授权状态和 JS-SDK ticket。生产前检查 `VITE_API_BASE_URL`、管理端构建路径及反向代理，保证 Cookie 登录链路同源；不要把测试域名、HTTP IP 地址或本地回调放进正式配置。

网页授权和 JS-SDK 的账号权限以服务号后台实际显示为准。参考入口：[网页授权](https://developers.weixin.qq.com/doc/service/guide/h5/auth.html)、[JS-SDK](https://developers.weixin.qq.com/doc/service/guide/h5/jssdk.html)。

## 本次实现

1. 服务号菜单打开管理端微信入口；在普通微信中自动发起 OAuth，其他浏览器给出进入微信的提示。
2. 服务端使用 `snsapi_base` 获取 OpenID，不依赖微信昵称、头像或企微通讯录。
3. 以 AppID 和 OpenID 的组合建立独立账号。首次登录原子创建独立数据空间和一张草稿个人名片；重复、并发登录复用相同账号。
4. 新账号角色为 `card_owner`，不获得已有企业的成员或管理员权限。账号、成员关系或所属空间停用后不可重新开通绕过停用。
5. 个人用户可自行编辑姓名、职业、头像、联系方式和名片内容，再使用已有发布接口发布。企业员工的姓名、职位仍由企业身份资料维护。
6. 发布后的公开 H5 无需企微登录。分享支持已有二维码、复制链接，并为普通微信配置好友与朋友圈的标题和图片。

个人空间目前复用数据库的 tenant/company 隔离结构，通过 `workspace_kind=personal` 标记；它不代表用户已经认证某个企业。现有企微账号与微信账号不会按姓名、手机号或 UnionID 自动合并，加入已有企业需要后续单独的授权/邀请流程。

## 安全与数据变更

- 数据迁移：`20260921_0057`，新增 `wechat_accounts` 及最小权限的账号开通函数；前置迁移为已有工作区的 `20260909_0056`。
- OpenID 加密保存，查询使用 HMAC；账号路由表不向运行时数据库角色开放直接查询。
- OAuth state 在 Redis 原子消费并绑定 HttpOnly 浏览器 Cookie。授权码不重试；前端合并重复回调请求，避免 React StrictMode 重复交换。
- 应用会话继续使用原有访问凭证和 HttpOnly 刷新 Cookie，微信接口 token 不发给浏览器。
- 分享签名只允许本站当前已发布名片路径，保留实际查询参数、去掉 hash，不能为任意外站签名。
- JS-SDK 失败不阻断浏览；二维码和复制链接仍可使用。微信右上角菜单的真实分享效果需要真机验收。
- 禁用 HTTP 客户端的请求 URL 日志，防止微信接口参数中的 AppSecret 和授权码落日志。

## 验证与上线

本地已验证：OAuth 与状态安全、分享签名、前端登录入口及回调、构建，以及临时 PostgreSQL 16.2 上的全部迁移和个人名片开通—编辑—发布—公开读取链路。数据库用运行时普通角色验证了账号表访问限制及跨租户隔离。生产基线 PostgreSQL 18 仍需在预发布环境做迁移验证。
