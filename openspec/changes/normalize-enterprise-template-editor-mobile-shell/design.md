# Design: normalize-enterprise-template-editor-mobile-shell

## Design authority

- 项目 `DESIGN.md` 是设计宪法：克制、清晰、可信，延续既有移动端名片语言。
- `apps/card-web/src/prototype/BusinessCardPrototypeApp.tsx` 与本轮 390px 原版截图是公开名片外壳真源。
- 本变更采用 `inherit`，不创建新的品牌、导航体系或展示模板。

## Immutable mobile shell

以下结构在企业模板发布前后都必须存在：

1. 顶部标题与分享操作。
2. 企业头像、认证、简介、元信息和标签。
3. 内容目录：概览、介绍、业务、案例、资料、问答、AI。
4. 企业定位/价值主张面板。
5. 原固定内容区块和原底部咨询/合作操作。

模板块作为可选扩展内容进入上述内容流，不接管外壳，不改变固定目录的语义。

## Editor information architecture

- 顶部：返回/标题、草稿状态、预览、保存、发布。
- 左侧：基础设置与“页面目录”。目录明确区分“固定模块”和“自由模块”；固定模块不可删除，可自由模块可新增、排序、复制和删除。
- 中间：按真实移动名片顺序显示画布，固定模块以紧凑摘要呈现，自由模块可就地选中。
- 右侧：仅显示当前选中对象的设置；移动预览采用与公开名片相同的外壳结构。
- 窄屏：目录、画布、设置改为分段切换，操作与内容不横向溢出。

## Visual inheritance

- 使用既有 `bp-*` 颜色语义：白底、浅薄荷信息面、青绿色激活/强调、深灰正文、细边框和中等圆角。
- 使用原名片短竖线分节标题、目录下划线、浅色 chips 和底部主次按钮。
- 禁止自定义皇家蓝渐变头图、大面积后台灰卡、玻璃拟态或与名片无关的装饰。
- 桌面编辑器可提高信息密度，但预览和画布中的名片内容必须保持移动端比例与节奏。

## Rendering strategy

- 删除“有发布模板就隐藏原目录/固定模块”的条件。
- `EnterpriseTemplateBlocks` 继续处理受控模板块，但输出原名片区块结构和 token。
- 模板块插入企业定位面板之后、固定企业介绍之前；原固定区块继续渲染，保证旧导航与业务路径完整。
- 现有 JSON、草稿/发布版本和身份投影契约保持不变，降低数据与 API 风险。

## Accessibility and resilience

- 所有模块选择、排序、复制和删除保留键盘可达名称。
- 目录激活态不能只依赖颜色；使用文字权重与下划线共同表达。
- 空自由模块、失败图片和无效资源继续安全降级，不影响固定模块和操作栏。

## Baseline verdict

| Dimension | Baseline | Reason |
| --- | --- | --- |
| 原结构完整性 | 1/5 | 发布模板后目录与固定模块被隐藏 |
| 视觉一致性 | 1/5 | 编辑器预览使用独立皇家蓝/后台卡片语言 |
| 编辑可理解性 | 3/5 | 功能齐全，但固定与自由内容的关系不清楚 |
| 响应式可用性 | 3/5 | 可展示预览，但不是原移动端外壳 |
| 功能完整性 | 5/5 | 保存、发布、媒体、案例和员工投影已有证据 |

目标：全部 Hard Gates 通过；结构完整性、视觉一致性、编辑可理解性与响应式可用性均达到 4/5 以上，功能完整性不得回退。
