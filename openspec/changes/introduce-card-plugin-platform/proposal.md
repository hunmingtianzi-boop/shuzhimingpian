## Why

当前名片已经拥有可排序的页面块、共享公共渲染器、版本化草稿/发布快照和部分 Provider 接口，但扩展一个新能力仍需要同时修改前端联合类型、渲染分支、后台编辑器、后端大型校验模型和路由装配。随着预约、地图、直播、表单、CRM、AI 工具等能力增加，这种集中式扩展会持续放大回归范围，也无法形成按企业启停、授权、升级和回滚的产品能力。

本变更建立第一期受控插件平台：插件是平台随版本交付的可信扩展单元，宿主负责租户、安全、发布和审计，插件通过稳定合同贡献名片块。FAQ 与快捷入口作为两个样板插件，验证从后台编辑、服务端校验与数据解析，到发布快照和公共渲染的完整闭环。

## What Changes

- 新增版本化插件清单、插件注册表、宿主 API 版本和能力授权合同；插件 ID、贡献 ID 和版本在所有运行面保持一致。
- 新增统一的插件块文档。新草稿保存 `plugin_id`、`plugin_version`、`contribution_id` 与插件自有 `config`，发布快照固定经过验证的精确插件版本。
- 新增前端公共渲染、后台编辑和后端校验/解析注册表；核心宿主按贡献查找实现，不再为每个样板块增加集中式类型分支。
- 将 FAQ 与快捷入口迁移为首批内置插件，并保留现有 `faq`、`action_collection` 页面块的确定性兼容投影。
- 新增企业级插件启停、权限授予、审计、紧急停用和安全降级规则；`identity` 作为不可卸载、不可隐藏的系统贡献继续由平台保证。
- 新增商业功能目录、基础版/专业版/企业版套餐、企业套餐分配、合同计费信息和逐功能覆盖开关；最终权益由服务端统一解析并强制执行。
- 企业后台菜单、直接路由、公开名片能力和受控 API 使用同一功能 ID，关闭能力不能通过直接调用接口或启用名片插件绕过。
- 为后续后台页面、API Router、Worker Handler、AI Provider 和外部集成插件预留贡献类型，但本期不迁移这些业务模块。
- **BREAKING（仅新文档合同）**：新保存的页面编排采用插件块合同；旧草稿和已发布快照继续通过兼容适配器读取，不做破坏性重写。

## Capabilities

### New Capabilities

- `plugin-runtime-contract`: 平台以版本化清单发现可信内置插件，校验唯一性、宿主兼容范围、能力声明和跨运行面一致性。
- `card-block-plugin-host`: 名片公共端、后台编辑器和 API 通过注册表运行插件块，并以 FAQ 与快捷入口完成端到端样板迁移。
- `tenant-plugin-lifecycle`: 平台控制插件版本可用性，企业在权限范围内启停插件，发布快照固定版本并支持审计、熔断和安全降级。
- `commercial-feature-entitlements`: 平台按企业配置套餐和功能覆盖，企业端只消费最终权益，服务端对商业能力实施权威 Feature Gate。

### Modified Capabilities

- `card-page-composition`: 页面块从集中式 `type` 联合演进为版本化插件贡献引用，同时保留旧页面块兼容投影。
- `interactive-card-composer`: 编辑器从集中式块检查器演进为由插件贡献编辑器、默认配置和发布就绪检查。

## Impact

- 共享包：新增插件合同、注册表、宿主能力接口和跨运行面一致性检查。
- 访客端：按页面实际使用的插件懒加载公共渲染贡献；缺失或停用的可选插件安全隐藏。
- 管理端：插件提供块目录元数据、默认配置、编辑器和就绪检查；插件启停与权限状态可见。
- API：插件注册表负责配置校验、公司范围资源解析、发布归一化和公共投影；服务端保持最终权限权威。
- 数据：新增平台插件版本与企业安装状态；页面文档增加插件引用合同，历史文档保持可读。
- 商业化：企业设置保存套餐、计费周期、可选合同价格和功能覆盖；价格不写死在业务逻辑中，支付和自动续费仍由后续账单系统负责。
- 运维：新增注册冲突、版本不兼容、解析失败、熔断和降级指标；不新增外部服务或端口。
