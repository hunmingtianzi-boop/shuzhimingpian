## Acceptance Criteria

- AC1：导航出现“资料导入”，四个内容页右上角均可进入同一工作台并保留来源场景。
- AC2：批次列表显示企业内编号和可编辑名称，普通 UI 不显示 UUID；重命名刷新后仍保留，陈旧版本返回冲突。
- AC3：桌面候选审核一次只展开一条，分类/状态/置信度可筛选，原文证据可展开，底部操作固定；390px 不出现页面级横向溢出。
- AC4：高置信候选可批量选择并在汇总确认后写入草稿；中低置信不会被静默接受。
- AC5：产品、案例、FAQ 发布前显示关联名片数量和名称；确认集合变化时拒绝发布并要求刷新。
- AC6：发布后所有引用名片读取同一新版本；回退后网站公开页恢复旧内容，名片布局和顺序不变。
- AC7：资料导入工作台显示处理中、待审核、已完成、部分失败和失败状态，并提供安全重试/继续审核。
- AC8：只通过真实网站完成一次完整企业流程，不用数据库脚本或直接 API 代替页面操作。

## Evidence

- API：focused pytest 覆盖创建/命名/重命名/批量接受/影响预览/确认冲突/发布/回退与跨租户拒绝。
- Admin：focused Vitest、TypeScript build、OpenAPI 同步检查。
- Browser：从登录页开始，页面上传测试资料、重命名批次、生成并审核四类候选、发布内容、打开关联名片验证、回退后再次验证；记录关键步骤截图。
- Browser 环境：桌面和 390px；检查关键操作可见、无相关 console error、无页面级横向滚动。
