## Product Decisions

1. 导入是公共操作，不是内容分类；企业资料、核心业务、案例和 FAQ 继续作为真实内容源。
2. 独立资料导入工作台保存每次任务批次、进度、候选、接受/忽略结果和原始来源。
3. 批次主标识为 `#序号 + 可编辑名称`；单文件默认取文件名，多文件默认“首文件等 N 份资料”。
4. 候选只生成草稿。高置信候选可在二次汇总后批量接受；中置信逐条复核；低置信进入待判断。
5. 员工/企业基础资料仍实时读取单一数据源。产品、案例、FAQ 的公开内容采用草稿/已发布版本语义；名片布局只保存引用和展示规则。
6. 发布或回退前必须展示受影响名片，确认后原子切换已发布版本；不逐张复制内容。
7. 第一阶段只做工作台内通知；平台建企导入和权限细分延期。

## UI Direction

继承项目已批准的“克制、清晰、可信”设计宪法：白色与浅青承托、深蓝文字、品牌蓝只用于主要动作、8px 圆角和轻边框。不增加渐变玻璃、巨型 KPI、同形卡片墙或 AI 装饰图标。

桌面导入工作台使用三段式任务布局：左侧批次/分类列表，中间候选列表，右侧单条编辑与证据。真正需要高频浏览的列表保持扁平，详情通过选中态和渐进展开出现；底部动作固定。窄屏改为“任务列表 → 候选列表 → 候选详情”的逐层页面，不压缩三栏。

## Data Design

- `knowledge_import_batches` 增加 `sequence_number`、`display_name`、`version`，企业内序号唯一且正整数。
- 批次创建在同一事务内取得企业级 advisory lock 后分配 `max(sequence_number)+1`，避免并发重复。
- 重命名使用 `expected_version` 乐观锁；名称长度 1–120，服务端裁剪空白。
- 内容发布修订采用通用、租户隔离的不可变快照：resource type/id、revision number、payload、actor、created/published/rolled-back 时间。
- 关联名片由当前已发布模板中的 `product_ids`、`case_ids`、`faq_document_ids` 或 FAQ `all_published` 规则推导；预览与确认时都重新计算并校验 digest。

## Failure Rules

- 批次并发编号、跨企业重命名、陈旧版本、批量接受中任一越权为硬失败。
- 发布确认时关联名片集合变化返回 409，要求重新确认，禁止静默扩大影响。
- 回退不删除后续修订，只生成新的当前发布指针/修订事件。
- 现有导入 Worker、已导入批次和公开内容不得因 UI 重构丢失。
