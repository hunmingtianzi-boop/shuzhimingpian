## Why

现有企业名片编辑器把“原名片目录”“旧业务/案例段落”和“自由模块”维护为多套结构。虽然局部模块可排序，但公共页仍按类型放入固定槽位，造成目录、预览与发布页不一致，业务案例也无法成为真正可调的页面内容。

运营人员需要编辑一张可发布、可交互的移动名片页面：基础名片的信息应继续来自企业或企业员工，但它本身也必须能够与其他块一起拖动排序。

## What Changes

- 建立一份版本化的 `PageBlock[]` 页面编排真源，供草稿、发布快照、编辑器、目录和公开名片共用。
- 将基础名片建模为可排序的 `identity` 块：数据字段来自企业/企业员工映射，默认不可隐藏。
- 将企业介绍、业务、产品、案例、资料、视频、联系方式等收敛为同级内容块；业务和案例以受权限约束的内容引用保存，不复制成静态快照。
- 将公共名片改为按块顺序渲染，目录自动从可见且启用目录的块派生；保留既有详情、联系、AI、隐私等可操作入口。
- 将后台编辑器改为“结构列表 + 同一公共页画布 + 属性面板”；拖拽后立即同步画布、目录与草稿，并提供单独打开的真实公开页预览。
- 为既有名片提供兼容性转换，使尚未保存新编排的卡片继续按历史内容可用地展示。

## Capabilities

### New Capabilities

- `card-page-composition`: 页面块协议、基础名片数据映射、内容引用、排序与兼容转换。
- `interactive-card-composer`: 后台真实页面画布、拖放编排、块属性编辑与可操作预览。
- `derived-card-directory`: 从发布页面块自动生成内容目录、滚动定位与选中同步。

### Modified Capabilities

- 无；仓库当前没有已归档的 OpenSpec 主规格，本次以新增能力建立可验证契约。

## Impact

- 后端：模板验证、草稿/发布投影、公开卡片 API 和业务/案例引用解析。
- 后台：`EnterpriseTemplateEditor`、卡片创建/编辑流程、拖放与预览路由。
- 移动端：`BusinessCardPrototypeApp` 及其目录、内容渲染与兼容默认值。
- 测试：API 契约、拖放/目录同步、真实公开页交互、旧卡兼容和移动浏览器验证。
